# MYON v0.01 — 새로운 시작

현행 MYON GitHub Pages 기반(Vue 3 + Vite)을 유지하는 **로컬 우선 철도 운영 게임의 첫 작동 버전**입니다.

## 이번 버전에서 실제로 가능한 것
- **초기 상태에는 회사도 자금도 없습니다.** 운행 종료 시간 역시 연구 전에는 표시되지 않습니다.
- 기관차 L-001, 객차 C-001/C-002가 개별 ID 및 위치로 관리됩니다.
- 기본 노선(서울 → 대전 → 부산)에서 기관차를 운행할 수 있습니다.
- 운행 시간은 시작할 때 내부적으로 결정되고, 브라우저를 닫아도 현실 시간이 경과하면 운행이 완료됩니다.
- 운행이 끝나면 기관차와 연결 객차의 위치가 도착역으로 갱신되고 완료 횟수를 누적합니다.
- **고정배차 전**이므로 완료 운행의 상세 기록은 즉시 폐기합니다. 누적 완료 횟수는 유지합니다.
- 운행 1회 완료 시 `노선 설계` 연구를, 3회 완료 시 `시간 관측` 연구를 완료할 수 있습니다.
- 노선 설계 연구 후 사용자가 직접 노선을 추가 및 삭제할 수 있습니다.
- **IndexedDB 자동 저장** 및 `save.json` 단일 파일 내보내기/불러오기를 지원합니다.
- JSON에는 개인 노선, 개별 차량, 현재 운행, 연구, 진행 상태, 미래 확장 영역을 모두 담습니다.

## 향후 단계 (이번 버전에는 작동하지 않음)
연결/분리 편성 조작, 고정배차, 회사 설립, 자금·실제 차량가격·리얼모드, 복합열차, 폐색, 항공 ATC 등은 기능별로 추후 추가 예정입니다. 표시된 로드맵은 구현 완료 기능이 아닙니다.

## 실행 및 배포
```bash
npm ci
npm run dev
npm test
npm run build
```

- GitHub Pages 경로는 기존과 동일한 `/MYON/`입니다.
- **기존 `.github/workflows/` 폴더는 ZIP에 포함하지 않았습니다.** 현재 저장소의 GitHub Actions 파일을 그대로 남기고 압축 내용을 업로드하세요.
- 사이트에 바로 반영되는 것이 아니라 사용자가 소스 ZIP을 기존 저장소에 적용한 뒤 배포됩니다.
- 배포 전 기존 라이브 사이트와 유저 저장 데이터를 백업하는 것이 좋습니다.

## 기존 데이터 보호
이번 버전은 전용 IndexedDB `myon-game-v001` 및 캐시 `myon-game-v001-cache`를 사용합니다. 이전 실험 버전의 로컬 저장소(`myon-local-v1` 및 기존 키)는 **삭제하거나 자동 변환하지 않습니다**. 다른 구조의 이전 백업 파일은 조용히 덮어쓰지 않고 불러오기를 거부합니다.

## 저장 주의 사항
- `save.json`은 **수동 내보내기 시점**의 백업입니다. 파일을 내보낸 뒤 계속 플레이하면 파일 내용은 자동으로 바뀌지 않습니다.
- JSON 불러오기는 기존 게임 진행 전체를 덮어쓰므로 사전 확인창이 뜹니다.
- IndexedDB는 브라우저에 종속됩니다. 주기적으로 JSON 파일을 외부에 백업하세요.
- 파일이 매우 커지면 JSON 직렬화 비용과 브라우저 메모리 사용량이 증가할 수 있습니다. 추후 대용량 스트리밍 백업을 개발할 수 있습니다.
- 공용 기준 데이터는 GitHub에 두고, 개인의 운영 내용은 `save.json`에 묶는 것이 기본 설계입니다. 첫 버전의 기본 노선은 오프라인 실행을 위해 게임 내에 포함되어 있습니다.
