# MYON 리온 고유 ID 및 종류별 넘버링 · v1

> 2026-11-18 최초 등록. **ID와 번호 등록 전용이며 게임 동작은 변경하지 않습니다.**

## 원본과 관리 범위
- GitHub `main`에 있는 `data/rions/registry.v1.json`이 리온 원본 신원 등록부입니다.
- `data/rions/id-lock.v1.json`은 최초 발급된 ID·번호와 구 임무 인덱스를 보호하는 잠금 기록입니다.
- 역할 리온 4종, 플레이형 리온 5종, 분야별 리온 150종 = 총 **159종**.
- 분야별 목록은 `public/myon-world-baseline.json`의 15개 계열 × 10개 분야에 대응합니다.
- 이 파일들은 게임 런타임에 연결되지 않았으며 하단 메뉴, 임무, 저장소, UI, 승인된 정식 버전을 변경하지 않습니다.

## 두 가지 영구 식별자
1. `id`: 기계가 참조하는 **절대 변경 불가능한 ID** (예: `rion.role.user`, `rion.field.mission-01.01`).
2. `number`: 종류별로 독립 부여하는 **영구 번호** (예: `USR-000001`, `AGR-000001`, `LOG-000001`).

- 번호는 `접두어-6자리 숫자`이며 접두어마다 `000001`부터 시작합니다.
- 이름 수정, 소속 이동, 발전단계·발견 상태 변경으로 기존 ID/번호를 다시 발급하지 않습니다.
- 삭제 대신 폐기 표시를 사용하고 폐기된 번호도 **절대 재사용하지 않습니다**.
- 신규 리온은 기존 레코드 사이에 삽입하지 않고 **끝에 추가**하며, 해당 접두어의 미사용 다음 번호를 발급합니다.
- ID와 번호는 모두 중복 금지입니다. 종류별 번호만으로 식별하지 않고 전체 접두어까지 함께 사용합니다.

## 종류별 접두어
- 역할: `USR` 유저 · `DEV` 개발 · `ENC` 백과 · `NAR` 스토리
- 플레이: `OBS` 관전 · `MGT` 경영 · `CRE` 창작 · `EXP` 탐험 · `STY` 스토리형
- 분야: `AGR` 농업 · `LFS` 축산수산임업 · `RES` 광업자원 · `MFG` 제조가공 · `ENE` 에너지 · `CON` 건설시설 · `TRN` 교통 · `LOG` 물류 · `COM` 상업금융 · `CUL` 관광문화 · `EDU` 교육연구 · `MED` 의료복지 · `ENV` 환경생태 · `PUB` 공공안전 · `TEC` 정보기술

## 구버전 인덱스 보호
- 기존 게임의 150개 분야는 0~149 배열 인덱스를 사용합니다.
- `legacyFieldIndex`는 **기존 번호와 신규 ID의 1회성 대응표**이지 영구 ID가 아닙니다.
- 초기 150종의 기존 배열 위치와 연결을 절대 이동하거나 재지정하지 않습니다. 추가 분야도 배열 순서로 신원 ID를 생성하지 않습니다.

## 유저 상태와 발견
- 발견하지 않은 리온은 유저 세이브에 기록하지 않습니다. **기록 없음 = 미발견**, 발견 시 처음으로 `stage:0` 상태를 기록하도록 후속 설계합니다.
- 리온의 기본 정의와 ID는 GitHub가 보관하며, 유저의 발견·단계·관계·임무 진행 상태는 유저 세이브에만 기록하도록 설계합니다.
- 유저 리온 미발견 시 하단 리온 메뉴 없음, 백과 리온 미발견 시 지식정보창 없음. 미발견이어도 기존 세계는 정상 작동합니다.
- 각 분야에 실제 엔티티가 여러 개 생성될 경우 '정의 ID'와 '개별 인스턴스 ID'를 추가로 분리합니다. 인스턴스 ID 규격은 추후 별도 결정합니다.

- 다음 커밋부터는 이전 커밋의 잠금 목록과 비교하여 기존 항목의 수정·삭제·순서 변경을 차단합니다.

- 공개 저장소에 비공개 이야기 설정을 추가하지 않습니다.
