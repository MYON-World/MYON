# MYON WORLD · 시민 월드 1차 내부 시작화면

## 버전
v0.13.70 (DEV 1차 연결)

## 현재 동작
- 통합 포털에서 DEV를 선택하면 **정확한 커밋 SHA의** `releases/<sha>/myon-next.html`을 엽니다.
- 기존의 `releases/<sha>/myon.html`은 계속 보관됩니다.
- LIVE는 기존 승인된 SHA `b320853655acbdf91a1567e9a9449aaade465c55`의 종전 게임을 그대로 실행합니다.
- 새 첫 화면은 `public/myon-next.html`, 이미지 자산은 `public/myon-city-hero.webp`입니다.
- DEV 진입 전 포털은 버전 검증 → 기존 파일 확인 → 새 파일 확인 → 개인 데이터 백업 및 재검증 → 프레임 입장을 지킵니다.
- 새 화면의 NPC·지명·이야기·도시 수치·복구 전후 상태는 **디자인 시안으로서 임시 값**입니다. 아직 실제 게임 이벤트나 저장에 연결하지 않았습니다.
- 1 real second = 1 tick의 인터페이스 확인용 임시 시계가 매초 갱신되며, 탭 비활성 후 복귀 시 경과한 실제 초를 계산합니다. 현재 날짜/영속적인 게임 시간의 정의는 아직 없습니다.
- 화면을 닫기 위한 `MYON_SAFE_UPDATE_CHECKPOINT`는 읽기 전용 시안이라 검증할 새 상태가 없으므로 성공을 반환합니다. 실제 상태 저장을 구현하면 **저장+재읽기 검증을 통과한 뒤에만** 성공하도록 교체해야 합니다.

## 재설계 때 이어받을 기능적 구조
1. **정적 콘텐츠 (GitHub)**: 도시, 구역, NPC, 대화, 사건 분기, 조건, 월드 변화 이미지/자산.
2. **새 게임 엔진**: 1초당 1틱을 기초로 월드 이벤트를 진행하되, 비활성/재진입 때 누락된 시간을 결정적으로 재처리.
3. **개인 상태만 세이브**: 현재 지역, 경험 레벨, 진행 중 이벤트와 시작 틱, 완료한 단계, 선택, 인간/NPC 관계 및 도시별 변화 델타.
4. **개인별 화면 단계**: 세계 데이터는 공통이지만 특정 장소·선택지·시설·연결 및 시간 이상 현상은 플레이어 기록에 따라 노출.
5. **세이브 설계 별도 진행**: 기존 운송 세이브는 신규 구조와 호환하지 않아도 되지만, 삭제하거나 LIVE에 덮어쓰지는 않음. DEV용 새 데이터베이스와 스키마, 가져오기/내보내기/재읽기 검증을 설계한 후 쓰기를 활성화.
6. **게임 진입 단계**: 포털과 검증 화면, 서버별 저장 분리, 불변 커밋 아카이브, 실패 시 미진입 정책은 계속 재사용.
