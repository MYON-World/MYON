# MYON WORLD · 시민 월드 1차 내부 시작화면

## 버전
v0.13.70 (DEV 1차 연결)

## 현재 동작
- 통합 포털에서 DEV를 선택하면 **정확한 커밋 SHA의** `releases/<sha>/myon-next.html`을 엽니다.
- 기존의 `releases/<sha>/myon.html`은 계속 보관됩니다.
- LIVE는 기존 승인된 SHA `b320853655acbdf91a1567e9a9449aaade465c55`의 종전 게임을 그대로 실행합니다.
- 새 첫 화면은 `public/myon-next.html`, 이미지 자산은 `public/myon-city-hero.webp`입니다.
- DEV 진입 전 포털은 버전 검증 → 기존 파일 확인 → 새 파일 확인 → 개인 데이터 백업 및 재검증 → 프레임 입장을 지킵니다.
- 새 화면의 NPC·지명·이야기·도시 수치·복구 전후 상태는 **디자인 시안으로서 임시 값**입니다. 아직 실제 게임 이벤트나 저장에 연결하지 않았습니다.
- 1 real second = 1 tick의 인터페이스 확인용 임시 시계가 매초 갱신되며, 탭 비활성 후 복귀 시 경과한 실제 초를 계산합니다. 현재 날짜/영속적인 게임 시간의 정의는 아직 없습니다.
- 화면을 닫기 위한 `MYON_SAFE_UPDATE_CHECKPOINT`는 읽기 전용 시안이라 검증할 새 상태가 없으므로 성공을 반환합니다. 실제 상태 저장을 구현하면 **저장+재읽기 검증을 통과한 뒤에만** 성공하도록 교체해야 합니다.

## 재설계 때 이어받을 기능적 구조
1. **정적 콘텐츠 (GitHub)**: 도시, 구역, NPC, 대화, 사건 분기, 조건, 월드 변화 이미지/자산.
2. **새 게임 엔진**: 1초당 1틱을 기초로 월드 이벤트를 진행하되, 비활성/재진입 때 누락된 시간을 결정적으로 재처리.
3. **개인 상태만 세이브**: 현재 지역, 경험 레벨, 진행 중 이벤트와 시작 틱, 완료한 단계, 선택, 인간/NPC 관계 및 도시별 변화 델타.
4. **개인별 화면 단계**: 세계 데이터는 공통이지만 특정 장소·선택지·시설·연결 및 시간 이상 현상은 플레이어 기록에 따라 노출.
5. **세이브 설계 별도 진행**: 기존 운송 세이브는 신규 구조와 호환하지 않아도 되지만, 삭제하거나 LIVE에 덮어쓰지는 않음. DEV용 새 데이터베이스와 스키마, 가져오기/내보내기/재읽기 검증을 설계한 후 쓰기를 활성화.
6. **게임 진입 단계**: 포털과 검증 화면, 서버별 저장 분리, 불변 커밋 아카이브, 실패 시 미진입 정책은 계속 재사용.

## v0.13.71 · 스크롤 없는 구성
- DEV 게임은 화면 높이 `100dvh`를 기준으로 페이지 스크롤 없이 배치됩니다.
- 도시 / 이야기 / 탐색 / 내 기록은 동일한 화면 크기의 별도 탭으로 전환됩니다.
- 도시 탭은 도시 풍경·시민 상태를 보여주며, 이야기 탭은 스토리 카드와 AI 진단을 표시합니다. 탐색과 내 기록도 별도의 시안 화면으로 열립니다.
- 모바일 및 낮은 화면 높이에서는 카드 크기를 줄이되, 탭 이동과 대화창은 유지합니다.
- 현재는 읽기 전용 UI 시안이므로 도시와 개인 기록은 아직 데이터베이스에 저장하지 않습니다.

## v0.13.72 · 도시 선택 및 첫 입성 시안
- DEV의 시작 화면은 리엔시(사람들의 이야기), 하렌(평화로운 시골마을), 세린시(산업과 경제)를 한 번에 소개합니다.
- 도시별 WebP 그림은 `public/myon-city-{lien,haren,serin}.webp`에 분리되어 있고, 선택 시 도시 풍경이 전환됩니다.
- 선택 → 입성 확인 → 첫 도착 → 첫 행동 4가지(대화/탐색/시설/머물기)가 클릭으로 작동합니다.
- 도시 소개는 각 도시의 분위기와 주제를 제시할 뿐, 고정된 줄거리·필수 복구 순서를 부여하지 않습니다.
- 모바일은 스크롤 없이 화면 크기에 맞추어 표시합니다. 상단의 시작화면 이동 버튼은 포털이 소유하며, iframe 안의 중복 버튼은 숨깁니다.
- 새 시민 월드의 실제 게임 진행·세이브는 아직 연결하지 않았습니다. 기존 LIVE 고정본과 저장 DB는 유지됩니다.

## v0.13.73 · 최초 캐릭터 생성 및 도시 이동 잠금
- DEV는 최초 접속 시 **캐릭터 만들기 → 첫 도시 선택 → 첫 입성** 순서로 시작합니다.
- 이름(2~12자), **남자/여자 실사형 이미지 필수 선택**, 플레이 성향(자유로운 삶 / 사람과 이야기 / 탐험과 발견 / 경제와 성장)을 입력합니다.
- 선택한 성향은 첫 임무의 우선 안내에 반영되지만 다른 분야 행동을 잠그거나 직업을 확정하지 않습니다.
- 캐릭터 ID는 이름과 분리하며 `MYON_DEV_CITIZEN_V1` 로컬 저장 키와 보조 백업 키에 캐릭터·첫 도시만 저장합니다. 재접속 시 생성 화면을 다시 표시하지 않습니다. 이 저장은 브라우저/기기별이며 교차 기기 동기화는 없습니다.
- 도시 입성은 현재 도시를 확정합니다. 이후 시작 화면을 거쳐 도시 선택으로 되돌아가 이동하는 경로는 차단했고, 교통시설이 마련되기 전에는 도시 간 이동 기능을 제공하지 않습니다.
- 실제 NPC 활동·시설·퀘스트의 진행과 세이브, 서버 기반 백업 및 도시 간 교통 시스템은 이후 단계에서 구현합니다.
- 기존 LIVE 승인본 및 그 저장소는 수정하지 않습니다.

## v0.13.75 · DEV 버전별 저장 초기화 정책
- DEV는 **버전 번호(예: 0.13.75→0.13.76)**가 바뀌어 접속할 때만 처음부터 시작하며, 동일 버전에서는 재접속·새로고침 후 진행 기록을 이어갑니다. 테스트 수정 커밋만 증가할 경우 초기화하지 않습니다.
- 서버 입장 전에 대상 아카이브 확인 후 `prepareDevVersion`을 실행합니다. 이전 버전에서 남은 `MYON_DEV_` 로컬 저장 키, DEV 전용 IDB(`myon-v00804-progress-dev`), 공유 백업 저장소 안의 DEV 레코드만 정리합니다. 삭제 작업이 실패하면 오류를 표시하고 입장을 중단합니다.
- iframe의 캐릭터 기록은 `MYON_DEV_CITIZEN_V2_<version>` 키로 분리하여 오래된 캐릭터·도시 정보가 새 버전에서 읽히지 않도록 방지합니다. DEV 화면 직접 로딩도 버전 식별자를 확인하며, 미리보기는 별도 키를 사용합니다.
- 초기화 후 **캐릭터 생성 → 기존 도시 선택 화면 → 첫 입성**을 다시 진행합니다. 같은 버전에서는 입성한 도시와 캐릭터가 유지됩니다.
- LIVE/TEST DB, LIVE·TEST 백업, LIVE 승인된 릴리스의 내용은 변경하지 않습니다.
- 새 NPC·임무·시설 저장 시스템도 DEV에는 `MYON_DEV_` 전용 키 또는 버전별 저장 구조를 사용해야 합니다.
