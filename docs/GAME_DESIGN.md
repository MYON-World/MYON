# MYON 게임 설계 — v0.13.05 (현재 적용)

> 2026-11-09. 기존 v0.13.04 동작·진행시간·저장구조를 수정하지 않고 남은 시간 **표시 방식만** 조정한다.

## 잔여시간 표시 규칙
- **2시간 초과** 남으면 `일 HH:MM`: 예 `3일 04:15`, `0일 02:01` (하루 미만이라도 `0일` 명시).
- **정확히 2시간 이하** 남으면 `HH:MM:SS`: 예 `02:00:00`, `01:59:59`, `00:00:09`.
- 2시간 초과에서는 초를 표시하지 않을 뿐, 실제 남은 시간과 자동 운행/공사 진행은 기존 초 단위 절대시각으로 계산한다. 카운트다운을 사용하는 임무/단계/정류장 대기 및 다음 임무 공급 표기에 동일하게 적용.
- 그 외 UI 위치·카드·임무 등장주기·30슬롯·왕복/복귀·단선/복선·확률·작업량·버스 철도 시간표·저장 `v01302-world` schema 2는 변경하지 않는다.

## 신규 철도건설과 유지보수 진행
| 임무 | 단계 순서 | 폐기 시점 |
|---|---|---|
| 신설철도 · 단선 | 현장 이동(30분~8시간) → 단선 구간 시공 1회 → 시공거리+접근거리 주행 복귀 | 전체 주행 복귀 완료 |
| 신설철도 · 복선 | 현장 이동(30분~8시간) → 첫 번째 선로 시공 → 되돌아오며 두 번째 선로 시공 → 초기 접근거리 주행 복귀 | 두 선로 완성과 접근거리 복귀 완료 |
| 철도보수 | 현장 이동 → 해당 구간 보수 1회 → 보수구간 거리+접근거리 주행 복귀 | 전체 주행 복귀 완료 |
| 도로보수 | 현장 이동 → 해당 구간 보수 1회 → 보수구간 거리+접근거리 주행 복귀 | 전체 주행 복귀 완료 |

- 신설철도 임무당 단선/복선 **랜덤 50:50**. 복선은 같은 구간을 돌아오면서 새로 한 선로를 시공하는 개념이므로 **총 시공량과 시공시간이 단선의 2배**. 작업능력은 기존 1km/일의 1개 선로 기준으로 적용. 기존 철도보수 1.5km/일, 도로보수 2km/일 유지.
- 기존 작업 거리 확률 **0.5–5km(65%), 5.1–20km(25%), 20.1–100km(9%), 100.1–500km(0.9%), 500.1–1000km(0.1%)** 그대로.
- 최초 현장 이동시간은 임무별 **30분부터 8시간까지 30분 단위 랜덤**. 접근거리 계산에는 게임 설계 가정 **20km/h**를 사용(이동거리 10~160km). 복귀 이동시간 역시 20km/h를 기준으로 실제 복귀거리에 따라 산정하므로, **복귀시간 자체는 8시간을 초과할 수 있음**. 이는 실물 제조사의 작업 제원으로 확인된 값이 아니라 임시 게임 기준.
- 이동 및 작업은 절대 타임스탬프 기반으로 독립 진행되며 오프라인·새로고침에도 같은 결과. 작업을 마쳤어도 장비가 돌아오기 전에는 임무 카드 유지. 30개 동시 임무 안에서 독립적으로 수행.

## 임무카드
- 공사·유지보수 **첫째 줄**: 왼쪽 임무명(신설철도면 단선/복선 포함) / 오른쪽 **이동중 또는 작업중** 상태 배지(복귀 단계도 이동중).
- **둘째 줄**: 왼쪽 **현재 단계 남은 거리** / 오른쪽 **최종 임무 종료까지 예상 남은 시간**.
- **하단**: 전체 임무 진행시간을 기준으로 한 얇은 진행바. 기존 차량 카드 스타일, 추가 줄 금지.
- 이동 단계는 거리/시간에 비례해 잔여거리 감소, 작업 단계는 시공 진도에 비례해 잔여거리 감소. 전체 종료시간은 최초 출발부터 마지막 복귀까지.

## 기존 저장 이관
- 저장 DB `myon-v00804-progress`, store `game`, key `v01302-world`, schema2 **그대로 유지**.
- v0.13.03 이하에서 작업 도중인 공사는 기존 작업 시작/종료 시각을 그대로 지닌 작업 단계를 유지하고, 과거 첫 이동 단계를 앞에 삽입하며 후속 복귀를 추가. **이미 완료한 작업 거리/진도는 리셋하지 않는다.** 새로 부여된 공사는 처음부터 이동 시작. 이관한 공사 복선 여부는 이전에는 존재하지 않았으므로 **기존 것은 단선형**으로 유지.

# MYON 게임 설계 — v0.13.01 (현재 적용)

## 운송 보유 한도
- 택시/화물차/버스·철도 보유 노선/항공기/선박의 보유 슬롯 합산 최대 **10개**. 노선 내부 출발 편성은 미포함.
- 매 1시간마다 랜덤 차량·노선을 공급하되 10개 이상이면 대기 공급 1건을 유지하고 신규 등장을 차단한다.
- 구버전 저장에 10개 넘게 존재하면 소유분을 강제로 제거하지 않는다. 자연 폐기로 10개 미만이 된 뒤 추가 공급을 재개하며, 저장 유효성 검사는 과거 최대 100개까지 허용한다.

## 건설·유지보수 단일 임무
- 별도 페이지/버튼 없이 차량 및 차량 등장 카운트 아래에 공사 카드 하나를 노출한다. 스크롤하지 않거나 미접속 중에도 시간 기준으로 작업 진행.
- 신규 철도건설 / 철도보수 / 도로보수 중 한 종류가 자동 선택되고, 공사 총거리는 극단적인 값까지 뽑히되 극장거리는 극저확률.
- 거리의 크기와 관계없이 **진행 중인 공사 하나**만 존재한다. 장비 종류별 일일 작업능력을 속도로 적용하여 매 초 표시 갱신. 모든 거리를 시공해야 그 임무가 종료되며 다음 임무가 바로 생성된다. 과거 임무를 현재 진행상태로 재등록하지 않음.
- 카드 구성은 딱 2줄: (1) 임무명, 총거리 (2) 진행률 막대, 시공거리/총거리, 퍼센트. 다른 공정·장비 패널 미노출.
- 교통 저장(`v01204-world`)과 별도로 `v01300-construction`(schema 1)에 공사 종류, 거리, 일일능력, 시작 시각, 난수 상태, 임무 번호 보존. 재접속 시 실제 경과로 여러 임무가 끝났더라도 순서대로 재현.
- **공식 MYON 게임 밸런스(0.13.01 확정)**: 신규철도 1km/일, 철도보수 1.5km/일, 도로보수 2km/일. 거리 분포(100m 단위) 0.5~5km 65%, 5.1~20km 25%, 20.1~100km 9%, 100.1~500km 0.9%, 500.1~1000km 0.1%. 실제 제조사 보증 제원이 아니며 기존 임무의 거리와 시공속도는 그대로 유지한다.
- 별도 장비 보유/현장별 동시 수주, 장비 구매, 공사비·재정, 장비 고장·점검, 도로 차단/철도 운영 중단 등은 아직 설계/요청되지 않았으므로 미구현.

# MYON 게임 설계 — v0.12.04 (현재 적용)

> 2026-11-08. 교통수단별 자동운행을 한 페이지에서 관람하는 세계. 실제 시간 1:1. 채팅의 30배속 시뮬레이션은 미리보기 전용.

## 등장과 보유
- 최초 택시 자동 지급. 이후 시간당 랜덤 교통수단 하나 공급, 최대 동시 소유 100개(모든 분야 공통). 가득 차면 대기 공급 1건이 다음 빈자리에 즉시 등장.
- 택시/화물차/버스/철도/비행기/선박을 랜덤 추첨. 항공 국내·국제선, 버스와 철도는 종류도 랜덤. 버스 4종: 마을/시내/광역/심야광역. 철도 5종: 트램/지하철/심야지하철/일반/고속.
- 같은 종류 버스/철도 노선 소유는 하나까지. 노선의 여러 출발 편성은 소유 1슬롯 안에서 파생. 자금·레벨·업그레이드·버튼·수동판매 없음.
- 개별 택시/화물차/항공/선박 운항 완료 100회 자동 폐기. 노선은 해당 주 마지막 배차까지(심야는 일요일 저녁 시작~다음 월요일 08시 포함), 전 차량 복귀 후 자동 폐기. 모든 편성은 왕복 후 즉시 소멸.
- IndexedDB myon-v00804-progress / game / v01204-world schema 1 신설; 이전 v01203-world 및 v01200-taxi와 다른 과거 키 보존. 이전 택시별 완료 수를 100회 신생명주기 내 나머지로 승계하고 새로운 속도/거리의 운행을 시작. 원본 누적 실적은 이전 키에 남음. 절대시각과 시드로 오프라인 운행/배차 재현.

## 개별 운송
| 종류 | 자동 운행 사이클 |
|---|---|
| 택시 | 랜덤 3~10km 주행 → 도착 +1회 → 10분 대기 |
| 화물차 | 상차30분 → 랜덤 5~15km 주행 → 하역30분 (+1회) → 대기60분 |
| 국내선 | ATC10분 → 비행1시간 (+1회) → 대기1시간 |
| 국제선 | ATC10분 → 비행2~15시간 랜덤 (+1회) → 대기1시간 |
| 선박 | 운항2~30일 랜덤 (+1회) → 다음 항해 즉시 시작 |

도로 차량/버스/트램 주행 15~25km/h; 실제 매 1초마다 결정되고 시드와 절대시간의 256초 난수 주기로 복원. 선박의 도착 후 대기시간은 아직 미정이라 넣지 않음.

## 노선 공통
- 1번에서 시간표 따라 편성 자동 출발. 출발시간/현재 위치만 보여주며, 새 편성은 아래에 추가, 마지막 역/정류장 도착 후 역방향 복귀, 1번 복귀 즉시 행 제거. 0대일 때 첫차/다음 출발 대기 카운트다운.
- 광역·심야광역: 1→2→3→4→5 → 고속도로2시간 → 6→7→8→9→10 → 9→8→7→6 → 고속도로2시간 → 5→4→3→2→1. 왕복 후 휴식 없이 해당 운행 편성 제거.
- 노선 슬롯은 해당 주 일요일까지 신규 배차 가능(심야는 다음 월요일 08시까지); 막차도 실제 복귀할 때까지 남고 마지막 복귀 후 노선 자동 파기.

| 구분 | 정류장/역 | 역간 이동 | 정차 |
|---|---:|---|---|
| 마을버스 | 20 | 350~850m 잠정 | 90초 잠정 |
| 시내버스 | 40 | 600~1400m 잠정 | 90초 잠정 |
| 광역/심야광역 | 10 | 450~1100m 지역 잠정 + 고속도로2시간×2 | 90초 잠정 |
| 트램 | 20 잠정 | 350~850m 잠정 | 90초 잠정 |

| 일반열차 | 10 | 30분 | 1분 |
| 고속열차 | 5 | 60분 | 1분 |

버스/트램의 지역 정류장별 이동거리와 정차시간은 확정되지 않은 미리보기 임시 수치이며 후속 조정 대상.

## 평일과 주말 시간표 (KST)
- 월요일~금요일 일반 버스 05:00 첫차~23:00 막차, 06~08·18~20 피크 5분, 나머지 20분. 토요일·일요일 05:00~21:00 전시간 20분.
- 일반 철도 평일 05:00~23:00, 피크 20분, 나머지 1시간. 주말 05:00~21:00 전시간 1시간.
- 심야광역버스·심야지하철은 저녁 18:00부터 다음날 08:00까지 하나의 서비스. 저녁 출발 요일이 평일이면 18~20/다음 06~08에 버스5분·철도20분, 그 외 1시간. 저녁 출발이 주말이면 아침까지 전부 1시간.
- 첫차/막차는 1번 정류장/역 출발 시각. 막차 이후에도 각 편성은 중단 없이 완주.

## 보관: 이전 v0.12.03 설계 (현재 미적용)

# MYON 게임 설계 — v0.12.03 (현재 적용)

> 2026-11-08. 누르지 않아도 계속 돌아가는 세계를 한 페이지에서 관람하는 것이 MYON의 기본 정책. 유저의 선택은 이후 자동 운영에 영향을 준다.

## 기본 화면
- 기존 임무 슬롯이 메인 페이지이며, **운영 메뉴 및 하단 탭은 삭제**. 상단 MYON/KST 날짜·시계만 유지하고 자금/업그레이드 요소는 모두 제거.
- 메인 리스트에는 지금 보유 중인 **택시별 1개 슬롯**을 표시. 첫 줄은 택시명·Lv.·운행 중 표시·**판매** 버튼, 둘째 줄은 운행 중 **남은 거리/누적 운영 횟수**, 대기 중 **대기 MM:SS/누적 운영 횟수**만 간단히 표시. 운행 진행 막대 유지.
- 차량 리스트 **바로 아래**에는 다음 차량 등장까지 남은 시간(HH:MM:SS)을 표시. 보유 한도 100대이면 한도 도달 상태로 표기. 설명 카드와 정산 알림 없음.

## 자동공급·보유·판매
- 최초 진입에 택시 1호차 무료 제공, 즉시 운행 시작. 이후 다음 공급시각마다 **차량 1대 자동 추가**(기본 24시간). 출석·인수·구입·자금 결제 없음. 공급 시간은 절대시각 기준이므로 접속하지 않아도 늘어남.
- 한도는 택시만이 아닌 미래 모든 분야의 차량을 포함해 **전체 합계 최대 100대**. 현재 택시 외 분야는 미구현. 한도 도달 시 공급 시각은 흐르지만 한도 초과 차량은 생성하지 않음. 판매로 자리가 나면 다음 예정 공급부터 자동 등장.
- 차량 **판매(방생)**는 Lv.1부터 허용하며 확인/보상/환급 없이 즉시 보유 목록에서 제거. 실수도 선택의 결과. 예전 차량 번호 재사용 없음. 이미 누적된 도시의 영구 공급시간 단축은 판매 후에도 유지.

## 차량별 운영·레벨
- 모든 택시는 **3~10km**(100m 단위) 이동을 랜덤 배정받아 자동운행. 기존 게임용 속도 **250m/s**로 주행. 운행이 끝날 때마다 그 차량의 **누적 운영 횟수 +1**; 돈·정산금액 없음.
- Lv.1은 0~99회 운영, **100회 달성마다 자동 레벨업**. Lv.20은 총 **1,900회**에서 만렙이며 레벨은 그 이상 증가하지 않음.
- Lv.1 이후 매 레벨 상승마다 운행 종료 후 대기시간 **30초씩 감소**. **Lv.1:10분 → Lv.2:9분30초 → … → Lv.19:1분, Lv.20:1분**. 대기 중에도 자동 시간이 흐르고, 종료되면 다시 운행.
- **Lv.20 달성 이후 추가로 완료한 운영**을 차량마다 독립 카운팅. 한 차량이 **100회/200회/300회…**를 각각 달성할 때마다 전체 **차량 추가 간격 1시간씩 단축**. 예: 택시1 100회·택시2 80회 → 총 1회(1시간) 단축; 두 차량 횟수를 합쳐 180회로 판단하지 않음.
- 공급주기 **24시간 → 최저 1시간**. 총 23개의 개별 100회 달성 단축 후 더 감소하지 않음. 보너스 발생 시 다가오는 공급 예정 시각도 1시간 앞당기되 과거 공급은 소급하지 않음. **이전에 얻은 단축은 차량 판매 후에도 사라지지 않음**.

## 저장·오프라인
- 신규 저장 `myon-v00804-progress/game/v01203-world`, schema 1. 기존 `v01200-taxi` 및 그보다 오래된 키는 그대로 보관.
- 첫 v0.12.03 진입 시 구버전 `v01200-taxi`에서 **완료 운행 횟수**를 택시 1호차 운영 횟수로 이관. 과거 화폐 잔액과 유료 요금레벨은 삭제하는 대신 기존 기록에만 남김. 당시 진행 중이던 운행은 1회만 새 시점에 마무리하고, 구버전 기간에 새 공급·레벨 보너스를 소급하지 않음.
- 매 차량의 독립 운영/만렙 이후 운영, 공급 간격, 다음 공급 시각, 운행/대기 상태를 저장. 미접속 기간에도 같은 자동운행·레벨 성장·차량 공급이 재현되며, 긴 미접속 기간은 완료한 사이클을 효율적으로 일괄 계산.
- 향후 다른 분야의 차량이 추가되어도 **전체 한도 100대**를 공유. 분야별 방생 조건은 개별로 설계 예정이며 아직 다른 분야·방생 수익은 미구현.

## 보관: 이전 설계 v0.12.02 이하

# MYON 게임 설계 — v0.12.02 (현재 적용)

> 2026-11-08. 택시는 처음부터 자동운행하며 운행 완료 후 대기시간을 가지는 거리 기반 임무 슬롯 게임. v0.12.01 이전 설계는 아래에 보관.

## 화면
- 상단 MYON/KST 날짜·시계/공용자금, 하단 **임무 / 운영** 메뉴 및 모바일 초압축 슬롯 유지.
- 임무의 택시 1호차는 **처음부터 자동운행**. 시작·자동운행 구매 버튼 없음.
- 운행 중 첫 줄: 택시명, Lv., 운행 중. **둘째 줄은 남은 거리와 실시간 정산예정금액 두 항목만**, 경과시간·설명 레이블 제거. 진행 막대 유지.
- 운행 완료 후 **정산 알림을 출력하지 않고 보유 자금에만 자동 반영**. 슬롯은 '대기 MM:SS'와 업그레이드 버튼으로 바뀌며, 10분 뒤 다음 운행 자동 시작.
- 운영 메뉴는 기존대로 **교통 → 택시**만 표시. 쿨타임 단축 업그레이드는 향후 운영 메뉴에서 정할 내용으로 이번 버전 미구현.

## 택시 운행·수익
- 매 운행 시작마다 **3~10km**, 100m 단위 무작위 운행거리 배정.
- 기본거리 **1.6km**. Lv.1 기본요금 **1,000원**, Lv.10 **10,000원**. 레벨당 기본요금 +1,000원.
- 운행 중 기본거리 초과 시 **131m마다 100원** 미터 요금 증가. 시간요금·심야요금은 미적용.
- 운행거리 및 속도는 레벨에 따라 변하지 않음. 이번 구현의 주행속도는 승인된 시연 속도 **250m/s**, 따라서 한 번 운행은 약 12~40초. 이는 실제 택시 주행속도가 아닌 게임 플레이용 임시 배율.
- 운행 1회 완료 후 **10분(600초) 쿨타임**. 완료 시각 + 10분 이후 다음 자동운행.
- 기본요금 업그레이드: 현재 레벨 × **100,000원**, 총 Lv.10 상한. 업그레이드는 **대기 중에만** 가능하며 현재 레벨의 기본요금만 증가. Lv.10이면 MAX.

## 시간과 저장
- 같은 IndexedDB `myon-v00804-progress` / `game/v01200-taxi`에 **schema 2**로 저장. 다른 구버전 키는 삭제하지 않음.
- v0.12.00~0.12.01(schema 1)의 잔액·완료 운행횟수·레벨을 이관. 이전에 시작해 아직 끝나지 않은 15초 수동 운행은 원래 보상으로 1회 정산 후 자동운행으로 전환. 새 상한보다 높은 과거 레벨은 Lv.10으로 제한.
- 실제 절대시각으로 거리·완료·대기를 재구성. 접속하지 않은 동안에도 운행과 10분 대기 사이클을 반영하며 같은 운행의 보상은 중복 지급하지 않음.

## 보관: 과거 설계 v0.12.01

# MYON 게임 설계 — v0.12.01 (현재 적용)

> 2026-11-07. 도시에서 일어나는 다양한 활동을 분야별로 추가하는 웹 방치형 + 개입형 게임. 첫 구현은 교통 / 택시 1호차.

## 구조
- 상단 MYON + 한국 표준시 날짜·시계, 보유 자금.
- 하단 **임무 / 운영** 두 개의 고정 메뉴.
- **임무**: 전체 분야 슬롯을 필터 없이 함께 표시하며, 현재 택시 슬롯 하나만 활성화.
- **운영**: 가로폭 100% 메뉴 버튼을 세로로 배치한 **분야 → 임무** 계층과 이전 메뉴 화살표. 현재 **교통 → 택시**만 표시하고 택시 운영 현황을 확인. 그 밖의 미구현 분야·임무·준비중 영역은 메뉴에 표시하지 않음.
- 기존 ATC 스타일을 유지한 모바일용 초압축 슬롯. 대기에는 운행·업글 버튼만, 운행 중에는 증가·감소 시간과 진행 막대.

## 택시 첫 단계 (수동 운영)
- 운행 시작을 눌렀을 때만 1회 운행. 진행 중에는 추가 조작 없이 완료 시 수익이 자동 정산되고 다시 운행 시작 버튼 표시.
- **잠정 게임 밸런스**: 운행 15초, 기본 수익 500원, 첫 업글 500원. 레벨 1 증가 시 다음 운행 수익 +100원, 다음 업글 비용 +250원.
- 운행 중 업글 불가. 자금이 부족하면 부족 금액 안내. 자동운행 해금, 다른 슬롯, 최종 레벨/상한과 정식 밸런스는 별도 설계 전 미구현.
- 실제 시각에 기반하여 접속하지 않은 시간 동안 이미 시작된 운행이 끝났다면 **그 한 번만 정산**. 자동 반복 정산 없음.
- 새 진행 기록은 IndexedDB `myon-v00804-progress`의 `game/v01200-taxi` (schema 1)로 독립 보관. v0.11.00 ATC 및 구버전 자료 보존.

# MYON 게임 설계 — v0.10.00 (과거 적용)

> 2026-11-01. 아래 역사 기록에 있는 v0.09.01 이하 규칙보다 본 문서가 우선함.

## 핵심
- MYON은 **원페이지 미니어처 도시 기반시설 방치형 게임**.
- 현재 **유저회사 1개만** 보유/표시. 다른 회사·미발견 카드·잠금 표시를 넣지 않는다. 추가 시설 조건은 차후 설계.
- 차량/운행, 임무, 교통분야, 레벨, 경험치, 하단 메뉴는 현 버전에서 비활성화.
- 초기 게임 자금 **0 M**. M을 소수점이나 원화로 임의 환산하지 않고 **정수 게임 자금**으로 계산·표시한다.

## 원페이지 레이아웃
- 상단 고정: MYON 타이틀과 한국 표준시 날짜/큰 HH:MM 시계.
- 바로 아래 고정: 라벨 없는 자금 패널, 정수 M, 오른쪽 정렬.
- 카드 목록은 본문에서만 스크롤(터치·휠 모두 허용), 스크롤바 숨김. 네비게이션 바 없음.
- 유저회사 카드: 첫째 줄 이름/정산 카운트다운, 둘째 줄 운영 중/정산 예정액. 카드 내부에 정산시간·수익 업그레이드 정보와 버튼 배치.

## 유저회사 운영
- 최초 무료 보유. 기본 시간당 1 M, 최초 정산주기 24시간, 1회 정산예정금 **24 M**.
- 실제 경과시간에 따라 자동 정산 및 즉시 다음 주기 시작. 오프라인 경과시간도 정산하고 재접속 후 중복 지급 방지.
- 정산시간 업그레이드는 지급 *빈도*를 변경할 뿐 시간당 수익을 바꾸지 않는다. 수익 업그레이드는 시간당 수익을 증가시킨다.

# MYON 게임 설계 기준

> 2026-10-28 / v0.09.01
> [확정] 사용자 요구사항 · [현재 구현] GitHub main · [미정] 후속 결정

## 기본 방향
- MYON은 도시의 다양한 사건을 다루는 간결한 방치형 + 경영 시뮬레이션 게임.
- 업그레이드가 많아지면 재미가 떨어지므로 꼭 필요한 기능만 추가하고, 도시 임무 선택과 실제 도시 변화의 게임성은 차후 개발한다.

## 화면 [확정/현재 구현]
- 왼쪽 MYON, 오른쪽 작은 `yyyy.mm.dd` + 큰 24시간제 `HH:MM`, KST 표준시, 1초 틱.
- 카드는 한 줄 `임무명 · 폐기 MM:SS · 시작`(미수락), `임무명 · HH:MM:SS`(진행 중). 제목·건수·자금·추가 상태 배너는 없음.
- 운영 종합판의 기존 임무 목록은 세로 스크롤, 스크롤바 숨김. v0.09.00 하단은 `운영 종합판 / 운영 / 메뉴 2 / 설정` 4개, 앞 두 메뉴만 이용 가능.
- **목록 정렬**: 미수락을 맨 위로 모으고 폐기까지 시간이 짧은 것이 먼저. 그 아래 수락된 임무는 완료까지 남은 시간이 짧은 것이 먼저. 해금 임무도 정렬에 포함.

## v0.08.07 레이아웃 복구 [확정/현재 구현]
- v0.08.05의 HTML·CSS를 화면 기본형으로 사용하며 버전 문자열·엔진 캐시값만 교체한다. 큰 시계, 한 줄 임무 카드, 하단 4개 메뉴와 간격, 색상은 동일하다.
- v0.08.06의 정렬은 기존 DOM 카드의 `style.order` 지정으로 구현한다. `list.append(...nodes)`로 노드를 다시 붙이지 않아 스크롤/화면 점프를 최소화한다.
- 자동수락 해금/24시간 진행, 10분 간격, 1분 쿨타임, 카드 10건 상한 등 0.08.06 기능은 모두 유지한다.

## 임무 제한과 시간 [확정/현재 구현]
- 전체 카드는 **기본 최대 10개**, `임무 수량 증가 2단계`(2시간 연구) 완료 후 **최대 20개**. 미수락 + 수락 + 업그레이드/해금 임무 합계이며 한도 미만일 때만 무작위 새 임무가 등장한다.
- 동시에 진행하는 수락 임무도 최대 10개. 제한 수치 비노출.
- 일반 임무: 최초 3건 즉시 등장. 신규 등장 간격은 초기 4~8.5초에서 연구 10회 완료 시 40~85초로 증가. 미수락 폐기시간은 초기 17~33초에서 최대 15~30분으로 증가. 수락 후 게임 소요시간은 임무별 현실 예상시간의 초기 10%(6~72분)에서 업그레이드 완료 시 100%가 된다.
- 종료된 임무는 목록에서 사라진다. 오프라인 경과시간을 재접속할 때 계산해 완료/폐기 정산. 미접속 중 무한 임무 누적 없음.
- 시간 표시·기본 IndexedDB 자동저장·오프라인 처리는 처음부터 제공(시간 연구/임시 저장 연구 없음).

## 자동 임무 수락 해금 [확정/현재 구현]
- 특별 카드 `자동 임무 수락`이 다른 임무처럼 무작위로 등장하고 미수락 시 폐기될 수 있다. 플레이어가 직접 시작하면 실제 경과시간 **24시간** 뒤 해금. 다시 등장하지 않음.
- 1단계 해금 직후 첫 **1분 쿨타임**. 이후 **10분에 최대 1건** 자동 수락, 각 수락 시 **1분 쿨타임** 적용. **2단계(24시간 연구) 완료 시 대기·쿨타임을 모두 없애고 빈 진행 슬롯에 일반 임무를 즉시 자동 수락**한다. 해금 및 1단계 수락 시각을 저장한다.
- 자동 수락은 미수락 *일반 임무* 중 폐기 예정시각이 가장 가까운 임무를 수락. 이미 폐기/완료되었거나 여유가 없으면 수락하지 않는다.
- 일반 임무 자동수락도 신규 시간표에 따른다. 자동 수락 해금 임무는 기존 24시간이며 카드/동시 진행 제한에 포함.
- 오프라인 상태에서 24시간 경과로 해금이 완료되면 재접속 시 영구 해금한다. 다만 미접속 동안 신규 임무를 만들어 10분마다 자동 수락한 것으로 소급하지 않는다.

- **임시 운행 밸런스 가정:** 주간 04:00~22:00 KST에만 새 운행 배정(심야운행 스킬 미해금); 주행 평균속도 30 km/h, 1.6 km 기본거리/131 m 증분과 MYON 기본요금 비례요율로 예상 운행료 계산. 실측 시간/요금과 게임 축소 비율은 사용자 확정 전 임시값. 밤이 되기 전 진행 중이던 운행은 완료 처리되지만 밤에 새 운행을 시작하지 않음.
- 자동운행은 오프라인 시간 경과 계산하되 **완료된 진행 운행 1회만 정산**하고 미진행 운행을 오프라인 기간 동안 무한 생성·반복하지 않는다. 주간 시간에 다시 시작.
- 미정: 기본요금·심야운행·지원축소·차량가격 스킬별 해금 레벨/조건·실제 비용, 심야 할증 요율, 실제 운행시간 최종 배율, 다른 운송 분야 도입 및 공용자금 외 추가 경제 규칙. 승인 없이 설정하지 않는다.
