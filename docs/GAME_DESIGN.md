# MYON 게임 설계 기준

> 2026-10-23 / 현재 코드 기준 v0.06.1  
> **[확정]** 사용자가 결정한 방향. **[구현]** GitHub main에 현재 들어 있는 수치·동작. 두 종류를 혼동하지 않는다.

## 게임 기본 방향 [확정]
- 여러 분야를 조금씩 키우면서 각 분야를 자동화하는 방치형 게임.
- 첫 개발 분야는 **교통 → 택시**. 다음 분야는 필요할 때 하나씩 개발하고, 개발된 분야는 동시에 운영한다.
- **모든 분야가 하나의 공용 자금**을 공유한다. 벌어들인 자금의 분야 간 재투자가 전략이다.
- 별도 도입 스토리를 추가하지 않는다.
- 기존 홈의 임무 리스트를 제거하고 분야 카드형 메뉴를 배치한다.

## 화면과 이동 [확정/구현]
- 상단 MYON 로고·날짜·시각, 바로 아래 현재 공용 자금, **설명 없이 바로 메뉴 카드**.
- 메뉴 계층: **홈 → 분야 → 교통 → 택시**.
- 하단: **← 이전메뉴 | 현 메뉴명 | 홈**.
- 카드는 세로 단일 목록 구조. 추가 분야는 해당 계층에 카드로 넣는다.
- 이전 버전의 임무판·메뉴는 별도 경로로 보존한다.

## 택시 차량 및 시 지원금 [확정/구현]

| 항목 | 적용 기준 |
|---|---|
| 차량가격 | **30,000,000M** |
| 최초 차량 | 시가 제공하는 택시 1대. 시작할 때 직접 구매 결제 없음 |
| 최초 차량의 미상환 지원금 | **27,000,000M**, 납부율 **90%** |
| 추가 차량 | 시 지원 비율 **0~90%** 선택 가능 |
| 추가 차량의 자기 부담금 | 차량가격 - 선택한 시 지원금 |
| 운행 수익의 시 납부 | 지원 비율만큼 납부하되 **미상환 잔액 이내**로 제한 |
| 납부금 처리 | 차량별 미상환 지원금에서 차감 |
| 중도 상환 | 공용 자금으로 **언제든 일부·전액 상환 가능** |
| 완납 이후 | 시 납부 종료, 즉시 **기본 자동운행**. ON/OFF 버튼 없음 |
| 시 지원금 0% | 구매한 순간부터 자동운행 |

- 완납 차량에는 지원금 잔액, 상환 진행률과 상환 버튼을 표시하지 않는다.
- 차량은 각자 운행하고, 정산한 순수익은 단일 공용 자금으로 합산한다.
- [주의] 첫 차량은 초기 구매 결제 없이 시작하며 현재 코드상 지원금 채무는 2,700만M이다. 첫 차량가격의 **나머지 10%에 대한 회계적 처리**는 별도 확정된 규칙으로 간주하지 않는다. 기존 동작을 임의로 바꾸지 않는다.

## 운행시간·교통정체: 현재 GitHub 상태 [구현]
- 운행거리는 약 **1~10km**에서 0.1km 단위로 무작위 생성한다.
- 정상 운행시간은 **1km당 3분**.
- **v0.06.1 실제 구현:** 운행 시작 시 임시 50% 확률로 **10~60분 교통정체**를 미리 결정해 기본시간에 합산한다.
- 거리요금 + 지연시간 × 200M/분을 **운행 시작부터 최종 예상요금으로 계산**한다.
- 이는 현재 코드의 구현 방식이지, 최근에 논의된 새 시간 변수·미터기 방식의 최종 합의가 아니다. **후속 변경 미리보기는 docs/NEXT.md 참조.**
