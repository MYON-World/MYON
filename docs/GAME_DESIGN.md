# MYON 게임 설계 기준

> 2026-10-28 / v0.09.00
> [확정] 사용자 요구사항 · [현재 구현] GitHub main · [미정] 후속 결정

## 기본 방향
- MYON은 도시의 다양한 사건을 다루는 간결한 방치형 + 경영 시뮬레이션 게임.
- 업그레이드가 많아지면 재미가 떨어지므로 꼭 필요한 기능만 추가하고, 도시 임무 선택과 실제 도시 변화의 게임성은 차후 개발한다.

## 화면 [확정/현재 구현]
- 왼쪽 MYON, 오른쪽 작은 `yyyy.mm.dd` + 큰 24시간제 `HH:MM`, KST 표준시, 1초 틱.
- 카드는 한 줄 `임무명 · 폐기 MM:SS · 시작`(미수락), `임무명 · HH:MM:SS`(진행 중). 제목·건수·자금·추가 상태 배너는 없음.
- 운영 종합판의 기존 임무 목록은 세로 스크롤, 스크롤바 숨김. v0.09.00 하단은 `운영 종합판 / 운영 / 메뉴 2 / 설정` 4개, 앞 두 메뉴만 이용 가능.
- **목록 정렬**: 미수락을 맨 위로 모으고 폐기까지 시간이 짧은 것이 먼저. 그 아래 수락된 임무는 완료까지 남은 시간이 짧은 것이 먼저. 해금 임무도 정렬에 포함.

## v0.08.07 레이아웃 복구 [확정/현재 구현]
- v0.08.05의 HTML·CSS를 화면 기본형으로 사용하며 버전 문자열·엔진 캐시값만 교체한다. 큰 시계, 한 줄 임무 카드, 하단 4개 메뉴와 간격, 색상은 동일하다.
- v0.08.06의 정렬은 기존 DOM 카드의 `style.order` 지정으로 구현한다. `list.append(...nodes)`로 노드를 다시 붙이지 않아 스크롤/화면 점프를 최소화한다.
- 자동수락 해금/24시간 진행, 10분 간격, 1분 쿨타임, 카드 10건 상한 등 0.08.06 기능은 모두 유지한다.

## 임무 제한과 시간 [확정/현재 구현]
- 전체 카드는 **기본 최대 10개**, `임무 수량 증가 2단계`(2시간 연구) 완료 후 **최대 20개**. 미수락 + 수락 + 업그레이드/해금 임무 합계이며 한도 미만일 때만 무작위 새 임무가 등장한다.
- 동시에 진행하는 수락 임무도 최대 10개. 제한 수치 비노출.
- 일반 임무: 최초 3건 즉시 등장. 신규 등장 간격은 초기 4~8.5초에서 연구 10회 완료 시 40~85초로 증가. 미수락 폐기시간은 초기 17~33초에서 최대 15~30분으로 증가. 수락 후 게임 소요시간은 임무별 현실 예상시간의 초기 10%(6~72분)에서 업그레이드 완료 시 100%가 된다.
- 종료된 임무는 목록에서 사라진다. 오프라인 경과시간을 재접속할 때 계산해 완료/폐기 정산. 미접속 중 무한 임무 누적 없음.
- 시간 표시·기본 IndexedDB 자동저장·오프라인 처리는 처음부터 제공(시간 연구/임시 저장 연구 없음).

## 자동 임무 수락 해금 [확정/현재 구현]
- 특별 카드 `자동 임무 수락`이 다른 임무처럼 무작위로 등장하고 미수락 시 폐기될 수 있다. 플레이어가 직접 시작하면 실제 경과시간 **24시간** 뒤 해금. 다시 등장하지 않음.
- 1단계 해금 직후 첫 **1분 쿨타임**. 이후 **10분에 최대 1건** 자동 수락, 각 수락 시 **1분 쿨타임** 적용. **2단계(24시간 연구) 완료 시 대기·쿨타임을 모두 없애고 빈 진행 슬롯에 일반 임무를 즉시 자동 수락**한다. 해금 및 1단계 수락 시각을 저장한다.
- 자동 수락은 미수락 *일반 임무* 중 폐기 예정시각이 가장 가까운 임무를 수락. 이미 폐기/완료되었거나 여유가 없으면 수락하지 않는다.
- 일반 임무 자동수락도 신규 시간표에 따른다. 자동 수락 해금 임무는 기존 24시간이며 카드/동시 진행 제한에 포함.
- 오프라인 상태에서 24시간 경과로 해금이 완료되면 재접속 시 영구 해금한다. 다만 미접속 동안 신규 임무를 만들어 10분마다 자동 수락한 것으로 소급하지 않는다.

## v0.08.08 임무시간 체계
- 사용자 확정: 일반 임무 32종은 임무별 **현실 작업시간 잠정 추정치의 10%**(90% 단축)를 소요한다. 작업 규모에 따라 현실 작업시간은 달라지므로 이 표는 실측 평균이 아닌 **게임 밸런스용 가정**이다.
- 현실 1시간 → 게임 6분: 생활 물자 운송, 긴급 물자 확보, 지역 의료 물품 확보, 지역 식료품 확보, 복지시설 물품 공급, 공공 급식 공급.
- 현실 2시간 → 게임 12분: 공공시설 점검, 도로 안전 점검, 통신 시설 점검, 정수시설 점검, 주거지역 전기 점검, 상업시설 안전 점검.
- 현실 4시간 → 게임 24분: 지역 전력 공급, 상가 물품 공급, 생활용수 확보, 공장 자재 운송, 가로등 정비, 정류장 시설 보수.
- 현실 6시간 → 게임 36분: 지역 환경 정비, 배수시설 정비, 물류 창고 정비, 공원 시설 정비, 폐기물 처리 지원, 지역 통신망 보수.
- 현실 8시간 → 게임 48분: 노후 시설 보수, 산업 설비 정비, 주거시설 보수, 산업단지 설비 보수, 학교 시설 보수.
- 현실 12시간 → 게임 72분: 노후 배관 교체, 하천 시설 복구, 산업 폐수 정비.
- **자동 임무 수락 해금 임무 24시간은 제외**하고 변경하지 않는다. 자동 수락 주기 10분·쿨타임 1분·전체 카드 10개 상한도 그대로.
- **이미 시작한 임무**의 완료예정시각(finishesAt)은 기존 저장값을 유지한다. v0.08.08 이후 수동·자동으로 새로 수락한 일반 임무부터 새 시간표를 적용한다.
- 초기 단계 임무 등장 간격 4~8.5초, 초기 미수락 폐기 17~33초(상위 단계에선 v0.08.11 적용), 오프라인 진행, 저장 DB `myon-v00804-progress`의 `game/v00806-main` (schema 3), 기존 해금 상태 유지.
- **v0.08.05 레이아웃 고정**: HTML·CSS·카드·시계·하단 메뉴는 손대지 않고 버전 제목과 엔진 캐시 키만 갱신한다.

## v0.08.09 순차적 시간 업그레이드 [확정/현재 구현]
- 32종 일반 임무별 현실 예상시간과 10%/100% 시간표 전체 내용은 **[임무시간 기준표](MISSIONS.md)**에 기록.
- 한 줄 홈 임무로 `임무시간 업그레이드 1`부터 `10`까지 무작위 등장. 사용자가 직접 시작한다. **앞 단계 완료 전 다음 단계 등장 불가**. 동일 단계 2개 동시 생성 불가.
- 연구시간 순서: **5분 / 15분 / 30분 / 1시간 / 2시간 / 3시간 / 6시간 / 9시간 / 12시간 / 24시간**.
- 연구 완료 비율 순서: **15/20/30/40/50/60/70/80/90/100%**, 초기 10%. 새로 수락하는 일반 임무부터 적용한다.
- 미수락 연구는 폐기되면 같은 단계가 재등장할 수 있고, 수락된 연구는 오프라인 경과시간으로 진행한다. 완료 레벨 `timeLevel`을 영구저장.
- 전체 카드 10개 제한과 동시 진행 10개 제한에 업그레이드 포함. **자동 수락은 일반 임무만** 수락하며 연구 임무는 제외.
- 별도 자동 임무 수락 해금 24시간은 비율에서 제외. 기존 저장 임무 완료시각과 해금/쿨타임 보존.
- **0.08.05 화면 디자인 고정:** HTML/CSS는 버전 문자열만 제외하고 그대로 유지.

## v0.08.10 자동 수락에서 시간 연구 제외 [확정/현재 구현]
- 자동 수락은 `kind='normal'`이면서 32개 등록된 일반 임무 이름과 일치하는 미수락·미만료 임무만 대상으로 한다.
- **임무시간 업그레이드 1회부터 10회까지 모두 자동 수락 제외.** 자동 수락 해금 24시간 카드도 자동 수락하지 않는다.
- 연구 업그레이드의 시작은 플레이어가 직접 `시작` 버튼으로 수락하는 방식만 사용한다.
- 후보가 연구뿐이면 자동 수락은 발생하지 않고 10분 간격/1분 쿨타임이 소비되지 않는다.
- 일반 임무 자동 수락(폐기 임박순, 10분에 1회), 저장, 오프라인, 레이아웃은 기존과 같다.

## v0.08.11 임무 등장·미수락 폐기시간 [확정/현재 구현]
- 시간 업그레이드는 일반 임무 진행시간뿐 아니라 **새 임무 등장 간격과 미수락 폐기시간을 함께 늘린다**. 상세한 0~10단계 표: [임무 목록 및 시간표](MISSIONS.md).
- 등장 간격 = 기존 4~8.5초 × (현재 임무시간 비율 ÷ 10%). 예: 5회 20~42.5초, 최종 40~85초.
- 미수락 폐기 상한은 초기 33초, 1~10회 완료 후 **1·2·3·5·7·10·14·19·24·30분**. 초기 최소 17초, 연구 후 최소는 각 상한의 절반. 10회 완료 시 **15~30분**.
- 일반 임무뿐 아니라 수동으로 수락하는 자동수락 해금·시간 업그레이드 카드에도 같은 폐기시간 적용(연구 진행시간은 그대로).
- 업그레이드 연구 완료 뒤 새 카드부터 새 폐기시간 적용. 이미 등장한 카드의 만료·완료 예정 절대시각은 보존.
- 새 연구 단계가 완료되면 다음 카드 등장 예약을 새 간격으로 갱신한다. 이전 버전 저장의 대기 예약도 **한 번만** 새 연구 단계에 맞춰 보정한다.
- 저장 레코드 및 스키마 그대로 두고 `timingVersion:1`만 추가해 이전 버전 예약과 구별한다. 기타 자동수락·연구·오프라인 규칙 동일.
- **0.08.05 UI 디자인을 변경하지 않는다**. 화면 크기·간격·색·카드·시계·하단 메뉴 원형 유지.

## v0.08.12 분야별 태그·교통 임무 [확정/현재 구현]
- 기존 도시 임무 32종 + 택시·버스·철도·항공·선박·우주 각 5종의 교통 운행 임무 30종으로 **일반 임무 총 62종**. 구체 임무시간표는 [MISSIONS.md](MISSIONS.md) 참조.
- 화면 태그 카드 순서는 **전체 / 도시 / 택시 / 버스 / 철도 / 항공 / 선박 / 우주**. 기존 시계 아래, 임무 목록 위에 배치하고 누르면 해당 분야만 화면에 보여준다.
- 카드 제목은 `[도시] 생활 물자 운송`, `[택시] 공항 택시 운행`처럼 분야 접두어로 구분한다. 저장된 임무명은 기존과 동일하다.
- 필터는 표시만 변경. 숨겨진 임무도 **10개 카드/동시 진행 한도, 만료·진행 시간, 저장/오프라인 처리, 일반 임무 자동 수락** 모두 정상 수행한다.
- 연구 임무는 도시 분야에 두고 기존 수동 시작만 유지. 일반 임무 62종은 10분 간격으로 자동 수락 대상 가능.
- 교통 임무도 기존 진행시간 10%→100%, 단계별 등장/폐기시간, 오프라인 시간표 동일. 이번 버전에 차량 소유·운행 노선은 추가하지 않는다.
- **기존 상단 MYON·KST 시계, 원래 한 줄 카드 높이/색상, 하단 4개 메뉴는 고정**하고 태그 및 제목 접두어만 추가한다.

## v0.08.14 자동 수락 2단계·임무 수량 2단계 [확정/현재 구현]
- `자동 임무 수락 2단계`: 기존 자동 수락 1단계(24시간) 해금 후 무작위 등장. 수동으로 24시간 연구를 마치면 일반 임무를 빈 동시 진행 슬롯(최대 10개)에 **대기·쿨타임 없이 즉시 여러 건 자동 수락**. 대상은 폐기 임박순.
- `임무 수량 증가 2단계`: 초기부터 무작위 등장 가능. 수동으로 **2시간 연구**를 마치면 표시/보관할 수 있는 임무 카드 총량 **10→20**, 반면 동시 진행 한도는 10으로 유지.
- 둘 다 완료 후 재등장하지 않으며, 일반 임무 자동 수락에서 제외. 미수락으로 사라진 연구는 이후 다시 등장 가능.
- 연구는 업그레이드 배율과 무관한 실제 시간 24시간/2시간이고 오프라인 완료/해금을 지원한다.
- IndexedDB 기존 `game/v00806-main` schema 3에 `autoInstantUnlocked`, `capacityUnlocked` 두 불리언을 추가. 레거시 세이브는 기본 false, 기존 연구·임무·대기/폐기·완료시각 이어받음.
- 기존 62개 일반 임무, 분야명 접두어, 미수락 폐기순·진행 완료순 정렬, v0.08.05 화면 및 잠긴 하단 메뉴는 유지.
- **자금 시스템은 사용자 지시대로 미포함.** 임무 보상·매출·요금·잔액 저장과 화면 표시를 추가하지 않음.

## v0.09.00 운영 메뉴 7개 분야 [현재 구현]
- 운영 종합판은 당분간 기존 0.08.14의 임무 리스트를 그대로 보여준다. 차량 카드로의 전환은 미구현.
- 가로 폭 100% 한 줄 카드 목록 7개: 택시 → 트럭 → 버스 → 철도 → 항공 → 선박 → 우주.
- 택시만 선택 가능하고 택시 운영 영역으로 진입/복귀할 수 있다. 택시 구매·강화 가격과 게임 규칙은 후속 설계 대상이며 실제 구매/강화 동작 없음.
- 트럭·버스·철도·항공·선박·우주는 `준비중` 텍스트와 잠금 아이콘, disabled 처리로 진입 불가.
- MYON/KST 시계, 종합판의 기존 임무 카드 CSS, 하단 4분할 디자인 유지. IndexedDB `v00806-main` schema 3, 임무 진행 및 오프라인 계산을 변경하지 않는다.

## v0.09 차량 방치형 게임 합의 방향 [미구현]
- 차량은 운송 분야와 무관하게 최대 30대 합산 보유. 각 차량과 NPC를 고정 연결. 철도 1편성은 차량 한 대로 계산하며 객차 증결은 하나의 편성 내 기능.
- 종합판에 최종 표시할 차량 카드: 2행 × 2열, 차량 이름 / 남은 시간 / 현재 운행 간단 정보 / 정산 받을 금액. 별도 차량 상세 화면은 만들지 않는다.
- 운송 분야별 구매 및 업그레이드는 운영 메뉴에서 담당하며, 현실 차량 가격/운행 수익/차량 데이터는 구체 설계 후 구현한다.
- 캐릭터 레벨이나 경험치 기능은 제외. 기존 임무를 무단 초기화하거나 새로운 수익·차량 데이터를 임의로 생성하지 않는다.
