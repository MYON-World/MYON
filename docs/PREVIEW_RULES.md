# MYON 게임 미리보기 제작 규칙

**상태:** 프로젝트 필수 작업 규칙  
**적용일:** 2026-11-18  
**목적:** 관리자에게 제공하는 모든 게임 디자인/동작 미리보기를 현재 실제 게임에 정합시키고, 승인되지 않은 UI 재설계·게임 코드 변경을 방지한다.

## 1. 화면 기준을 먼저 확보한다

1. 미리보기 제작 전에 GitHub의 **최신 실제 적용 코드**를 확인한다. 서버가 지정되지 않으면 개발서버를 기본 기준으로 삼는다.
2. 개발서버 화면은 `main`의 `public/myon-next.html`을 중심으로 `public/myon-dev-missions.js`의 실제 렌더링 및 `public/myon-dev-update.js`의 알림 구조를 함께 확인한다.
3. 기본 상단 구성(원형 M 엠블럼·서버명·KST 시계), 보유 자금 표시, 실제 임무 카드, 수락/보상/기여 3칸, 대기 폐기 진행바·진행 중 진행바, 스크롤 및 화면 너비 규칙을 유지한다.
4. 정식/정식 가속에 대한 미리보기라면 반드시 `src/core/myon-server-entry.mjs`의 고정 `LIVE_RELEASE`/`TEST_RELEASE` SHA를 확인하고 **해당 보관 릴리스의 코드**를 기준으로 한다. 최신 개발 코드를 정식 화면으로 가장하지 않는다.

## 2. 미리보기에서 변경 가능한 부분

- 사용자가 수정하자고 지시한 **요소만 변경**한다. 그 외 UI는 원래 구조·문구·스타일·배치·폰트·크기·색상·간격을 보존한다.
- 변경의 영향을 받는 요소가 있다면 필요한 최소 범위에서만 조정하고 무엇이 달라졌는지 명시한다.
- 단순한 와이어프레임, 다른 색상의 임의 UI, 텍스트 상자만 있는 대체 화면, 실제 게임에 없는 독립적인 모의 앱을 '현재 게임 미리보기'라고 제출하지 않는다.
- 새 하단 메뉴 등 현재 게임에 없는 부분은 **기존 화면을 보존한 채 해당 위치에 추가**한다.
- 예: UI 리온을 발견한 경우에만 현재 개발서버의 하단에 `리온` 메뉴를 새로 노출한다. 미발견 상태의 기존 화면에는 하단 리온 메뉴가 없다.
- 미리보기의 상단 업데이트 알림은 기존 `myon-next.html`의 자금 표시 아래 슬라이드다운 디자인을 그대로 따른다. 별도 카드나 토스트 알림으로 임의 변경하지 않는다.

## 3. 비교·동작 확인

- 상태 전환을 설명하는 요청에는 가능하면 **동일한 실제 화면에서 토글**을 제공한다. 예: UI 리온 미발견 ↔ 발견.
- 수락 버튼, 진행바, 임무 카드 등은 현재 게임의 디자인과 상태 구분을 따른다. 미리보기에서 실제 게임의 세이브/결제/보상 로직을 실행하지 않는다.
- 금전, 기여 수치, 시간, 버전 표기, 임무 수 등 실제 데이터가 주어지지 않은 값은 **예시 데이터**임을 사용자에게 밝힌다. 현재 게임의 계산값인 것처럼 표시하지 않는다.
- 실제 코드에 없는 동작은 '제안/미적용'이라고 분명히 표시한다. 구현된 것처럼 주장하지 않는다.
- 모바일과 PC의 실제 게임 반응형 규칙을 따라 미리보기를 구성한다. 화면을 감싸는 불필요한 새 프레임이나 장식 UI는 추가하지 않는다.

## 4. 실제 구현과의 분리

- **미리보기 요청은 게임 코드 수정·배포·커밋 허가가 아니다.** 실행 구현은 사용자가 명시적으로 요청할 때만 진행한다.
- 디자인을 승인받았더라도 '커밋 대기'라고 하면 적용하지 말고 설계 결정만 보존한다.
- `main` 커밋은 개발서버의 최신 자료가 되며, 정식과 정식 가속은 관리자 승인 SHA 고정이다. 미리보기 작업이나 새 `main` 커밋이 정식 실행 코드를 자동 갱신해서는 안 된다.
- 유저 세이브·자금·진행 중 임무·기존 ID를 미리보기 때문에 변경하지 않는다.

## 5. 제출 전 확인표

- [ ] 대상 서버에 실제 적용된 GitHub 파일/승인 SHA를 확인했는가?
- [ ] 현재 화면의 구조·스타일·기존 카드와 알림을 동일하게 사용했는가?
- [ ] 사용자 요청 변경점 이외에는 바꾸지 않았는가?
- [ ] 미발견/발견 등 비교 상태를 같은 화면에서 확인할 수 있는가?
- [ ] 예시값과 실제 실행값을 명확히 구분했는가?
- [ ] 미리보기와 실제 게임 적용·커밋을 명확히 구분했는가?

**우선순위:** 사용자가 실제 게임 화면과 일치하지 않는다고 지적하면 재확인 후 원본 UI 기준으로 다시 제시한다. 현재 게임 코드를 보지 않고 같은 오류를 반복하지 않는다.
